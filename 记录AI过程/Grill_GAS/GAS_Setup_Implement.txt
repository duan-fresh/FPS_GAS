### 3.2 `GE_InitAttributes`（属性初始值）{GreatHandling}

1. `AbilitySystem/Effects/` → 右键 → Blueprint Class → All Classes → 搜 `GameplayEffect`。
2. 命名 `GE_InitAttributes`。
3. Details 面板：
   - **Duration Policy = Instant**
4. **Modifiers 数组加 4 条，顺序不能错**：

   | # | Attribute | Modifier Op | Magnitude |
   |---|---|---|---|
   | 0 | MaxHealth | Override | 100.0 |
   | 1 | MaxShield | Override | 50.0 |
   | 2 | Health | Override | 100.0 |
   | 3 | Shield | Override | 50.0 |

   > ⚠ **Max 必须排在前面**：`UFPSAttributeSet::PreAttributeChange` 会把 Health
   > Clamp 到 `[0, MaxHealth]`。若 Health 先执行，此刻 MaxHealth 还是 0，血会被清成 0。
   > 代码里已加 `GetMaxHealth() > 0` 保护，这里是双保险。

**要调手感就改这两个数值**：MaxShield = 50 配合武器 Damage = 15，约等于能挡 3.3 发。

2. Details：

{Error}：UE 5.5 版本重命名了
原来的 On Active：现已更名为 On Burst
原来的 While Active：现已更名为 On Become Relevant
原来的 On Remove：现已更名为 On Cease Relevant

事件图里实现 **On Burst** / **On Become Relevant** 加粒子。先留空也能跑通逻辑。

> ⚠ UE5 把 `_Actor` 版这三个事件的**蓝图显示名改了**（C++ 函数名没变）：
> `OnActive` → **On Burst**、`WhileActive` → **On Become Relevant**、`OnRemove` → **On Cease Relevant**。
> 依据 `Engine/Plugins/Runtime/GameplayAbilities/Source/GameplayAbilities/Public/GameplayCueNotify_Actor.h:94`，
> 所以事件图里**搜不到 "On Active" 是正常的**。
> 另外 `WhileActive` 只在「变为可见」时触发一次（中途加入等），**不是周期事件** ——
> 持续火焰得自己在 Tick 里管理组件；周期表现真正对应的是 `GameplayCueNotify_Looping` 的
> `Recurring Effects`（对应每次 DoT 跳伤）。

## 5. 验收清单

### 5.1 单机（PIE，Play → 1 Player）

- [ ] 开局血条满血 **且有蓝色护盾条 + 护盾数字 50**
- [ ] 打自己/被打：**先掉护盾条**（蓝条变短、数字变小）
- [ ] 护盾归零后：**护盾条与护盾数字一起消失**，随后才掉红色血条
- [ ] 按下 `G`：扔出一个方块，抛物线落地 → 停住 → 放大成 5 米烟团 → 12 秒后消失
- [ ] 扔完立刻再按 `G`：扔不出来（冷却 15 秒）；等冷却好了能再扔
- [ ] 血量归零 → 死亡表现 → 3 秒后重生，**血条与护盾都是满的**（不是 0）

### 5.2 双人（PIE → Number of Players = 2）

- [ ] 玩家 A 扔烟雾，**玩家 B 也能看到烟**（验证 Actor 复制）
- [ ] 玩家 B 能**走进烟雾里**（验证可穿越）
- [ ] 玩家 B 朝烟雾开枪，**子弹能穿过去**（验证不挡子弹）
- [ ] A 打 B：**B 的护盾条掉、A 看到的 B 没有护盾 UI**（护盾/血量是 COND_OwnerOnly，只有本人可见）
- [ ] 给 BP_Rifle 配上 `BP_GE_Burn` 后：被打中的人身上出现燃烧 Cue，**每 0.5 秒掉一次血**，
      且掉血时**先扣护盾**；打死后燃烧立刻停止

### 5.3 常见故障对照

| 现象 | 原因 |
|---|---|
| 编译报找不到 `AbilitySystemInterface.h` | `.uproject` 没启用 GameplayAbilities，或没重新生成 VS 工程 |
| 开局血条是 0 / 血条不动 | `BP_FPSPlayerState` 的 **Init Attributes Effect** 没填 |
| 重生后立刻又死 | `BP_FPSPlayerState` 的 **Reset Attributes Effect** 没填 |
| 能开枪但打不掉血 | `BP_FPSCharacter` 的 **Damage Effect Class** 没填 |
| 按 G 没反应 | `BP_FPSCharacter` 的 **IA_Smoke** 没填，或 `IMC_FPS` 没绑按键 |
| 能扔但可以无限连扔 | `BP_GA_Smoke` 的 Cooldown GE 没填，或 `GE_SmokeCooldown` 少了 `Cooldown.Smoke` 标签 |
| 有烟但没有落地爆发效果 | Cue 蓝图不在 `Content/FPS_NetWork0/AbilitySystem/Cue/` 目录内 |
| 只有自己看得到烟 | `BP_SmokeCube` 的父类被改错（应继承 `FPSmokeCube`） |
| 蓝图编译报 BindWidget 找不到 | `ShieldBar_Fill` / `Text_ShieldValue` 名字拼错或控件类型不对 |
| 血条抖动 / 数值闪 | 大概率是动了 `HealthNumber` 的原有逻辑，恢复它 |

## 6. 已知注意事项

1. **`Content/FPS_NetWork0/AbilitySystem/Cue/` 是唯一的 Cue 目录。**
   `DefaultGame.ini` 里显式配置了 `GameplayCueNotifyPaths`，引擎不再 fallback 扫描整个 `/Game`。

2. **烟雾弹没有做客户端预测。** 按下到出现有 1 个 RTT 的延迟，这是既定取舍
   （与工程现有的 `Local_Fire` + `Sever_Fire` 模式一致）。

3. **`StackingType` 在 UE 5.8 已被标记废弃**，编辑器详情面板会隐藏它。
   DoT 的叠加规则固定为「同来源刷时长、不同 GE 叠加」，写在 C++ 构造函数里，蓝图改不了。
   `FPSDamageOverTimeEffect.cpp` 里用 `PRAGMA_DISABLE_DEPRECATION_WARNINGS` 包住了那行赋值。

4. **血量/护盾的复制已从 `UHealthComponent` 移到 `UFPSAttributeSet`**
   （两者都是 `COND_OwnerOnly`，语义不变）。`UHealthComponent` 上的
   `Health` / `MaxHealth` 现在是 GAS 的镜像，由 `SetFromGAS()` 单向驱动。

5. **`Source/FPS_NetWork0/Public/Interfaces/PlayerInterface.h:6`** 仍有一条指向
   `C:\Program Files\...` 的绝对路径 include。本机开发不受影响，
   但换机器或打 `TargetType.Game/Server` 时会编译失败。
   （本次按你的要求未改动它。）
